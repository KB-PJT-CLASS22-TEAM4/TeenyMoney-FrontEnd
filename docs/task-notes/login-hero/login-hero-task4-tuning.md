# 로그인 히어로 Task 4 — 영상별 초점 위치

> 이슈: #265
> 플랜: `~/.claude/plans/drifting-hatching-comet.md` §Task 4

## 1. 왜 이 값이 필요한가

시트를 올리면 영상 영역이 720px에서 220px로 줄어든다. `object-fit: cover`는 남은 창에
어느 부분을 넣을지 스스로 정하지 못하므로, 영상마다 "무엇을 남길지"를 지정해야 한다.

기하부터 확인했다. 원본은 **720×1264 세로 영상**이다.

| 상태 | 무대 | cover 배율 | 렌더 높이 | 세로 여백 |
|---|---|---|---|---|
| 접힘 | 375×720 | 세로 720/1264 = 0.570 | 720 | **0** |
| 펼침 | 375×220 | 가로 375/720 = 0.521 | 658 | 438 |

**접힌 상태에서는 Y값이 아무 효과가 없다.** 세로 배율이 이겨 렌더 높이가 정확히 무대 높이와
같아지므로 움직일 여백이 없다. 값이 실제로 작동하는 것은 펼친 상태뿐이고, 그때 보이는 것은
원본 1264행 중 **422행**이다.

```
보이는 원본 행 = [ Y% × 841.6 , Y% × 841.6 + 422.4 ]
```

이 관계를 먼저 세웠기 때문에 값을 감으로 흔들지 않고 계산으로 좁힐 수 있었다.

## 2. 무엇을 정했나

```js
const FOCUS = [
  'center 48%', // 001 세 얼굴 + 파란 모자
  'center 38%', // 002 활짝 웃는 부모 + 칠판
  'center 50%', // 003 카드를 든 아기
  'center 45%', // 004 코인이 뜬 휴대폰 화면
  'center 55%', // 005 세 얼굴 + 뒤쪽 저금통
]
```

X는 전부 `center`다. 접힌 상태에 가로 여백이 35px 있지만 피사체가 가운데 모여 있어
치우칠 이유가 없고, 펼친 상태에서는 가로 여백이 0이라 값 자체가 무의미하다.

## 3. 테스트

값을 눈으로 고르되, **고른 결과를 다시 눈으로 확인**하는 순서를 지켰다.

1. 각 영상의 3초 지점 프레임을 뽑아 인물 배치를 확인했다.
2. 후보 Y값으로 **펼친 상태에서 실제로 보일 375×220 크롭**을 ffmpeg으로 렌더해 확인했다.
   추측한 값을 그대로 코드에 넣지 않고, 그 값이 만드는 화면을 먼저 봤다.
3. 001은 첫 후보(42%)에서 아기 얼굴이 잘려 42 / 48 / 54를 나란히 비교했다.

| 001 후보 | 결과 |
|---|---|
| 42% | 아기 얼굴이 아래에서 잘림 |
| **48%** | **셋 다 온전함** |
| 54% | 아빠·엄마 머리가 위에서 잘림 |

브라우저 실측으로 적용도 확인했다 — 001 재생 중 시트를 펼친 상태에서
`object-position: 50% 48%`, 무대 높이 220px.

```
npm run build   built in 1.16s
npm test        17 pass, 0 fail
```

## 4. 판단 근거

**얼굴을 소품보다 우선했다.** 422행 창에 세 얼굴과 핵심 소품을 모두 담을 수 없는 영상이
있었다(001은 얼굴만 프레임의 36%를 차지해 창 높이 33.4%를 넘는다). 그럴 때는 얼굴을 살리고
소품 일부를 버렸다. 로그인 화면에서 전달할 것은 "가족"이지 소품이 아니다.

**드라마틱한 크롭을 피했다.** 계산상 얼굴을 꽉 채우는 값이 있었지만(001의 54% 부근),
머리가 잘리면 인형 캐릭터가 어색해 보인다. 여유를 남기는 쪽을 골랐다.

**값을 5개 배열로 둔 이유** — 영상을 교체하면 이 배열만 고치면 된다. 계산식이나 CSS를
건드릴 일이 없고, 위 주석의 공식으로 새 값을 바로 구할 수 있다.

## 5. 범위 밖

- **접힌 상태의 초점** — 세로 여백이 0이라 조정할 것이 없다. 무대 높이나 영상 비율이
  바뀌면 그때 다시 본다.
- **시간에 따른 초점 이동** — 각 영상에서 인물이 거의 움직이지 않아 한 값으로 6초 내내 맞는다.
  움직임이 큰 영상으로 교체하면 그때 필요해진다.
- **중간 크기 화면에서의 검증** — 812px 뷰포트 기준으로 맞췄다. 작은 화면에서는 시트가
  78dvh로 제한되어 무대가 더 얇아지므로, 실기기에서 한 번 볼 필요가 있다.
- **`.env.example` / `deploy-dev.yml` 배선** — Task 1. 배포 직전에 한다.
- **하단 검은 줄** — 원본 영상 하단 행이 오히려 중앙보다 밝아(001: 164 vs 147,
  005: 191 vs 175) 영상에 구워진 것은 아니다. Task 3에서 페이드/preload 타이머를 분리하고
  video에 배경색을 깔아둔 것이 원인 처리에 해당한다. 재발하면 다시 본다.
