# 모바일 Safe Area 기반 Edge-to-Edge 디자인

**GitHub Issue:** [#274](https://github.com/KB-PJT-CLASS22-TEAM4/TeenyMoney-FrontEnd/issues/274)

## 목표

iOS Safari와 홈 화면 PWA에서 노치, 다이내믹 아일랜드, 홈 인디케이터 주변까지 배경은 자연스럽게 이어지고 텍스트와 조작 요소는 안전영역 안에 남도록 한다. 인증, 금융, 결제, 라우팅과 API 동작은 변경하지 않는다.

## 원칙

- 배경색, 장식 이미지, 영상과 카메라 프리뷰만 화면 끝까지 확장한다.
- 제목, 금액, 입력 폼과 버튼은 `safe-area-inset-*` 안쪽에 둔다.
- Safe Area가 없는 브라우저에서는 inset이 `0px`가 되어 기존 레이아웃을 유지한다.
- CSS 환경변수를 공통 커스텀 프로퍼티로 노출해 화면별 숫자 복사를 막는다.
- 개발자 도구 검증을 위해 동일한 커스텀 프로퍼티를 테스트 클래스에서 덮어쓸 수 있게 한다.

## 화면별 동작

1. 로그인과 온보딩은 배경을 상단 상태바 뒤까지 확장한다. 로그인 시트와 온보딩 제목·버튼은 기존 Safe Area 보호를 유지한다.
2. 부모·자녀 홈과 일반 기능 화면은 상단 헤더의 배경만 확장하고 헤더 콘텐츠는 inset 아래의 기존 64px 영역에 배치한다.
3. 금융상품, 거래내역, 용돈과 퀘스트 화면은 공통 헤더 규칙을 통해 배경만 확장하며 정보 영역은 이동하지 않는다.
4. QR 및 퀘스트 촬영 화면은 검은 배경 또는 카메라 프리뷰를 화면 끝까지 채우고 안내·닫기·촬영 버튼을 inset 안쪽으로 이동한다.
5. 부모·자녀 하단 내비게이션은 흰 배경을 홈 인디케이터 뒤까지 채우고 기존 70px 조작 영역 아래에 bottom inset을 더한다.

## 검증

- Node 테스트에서 상태바 모드와 공통 Safe Area CSS 계약을 확인한다.
- 프로덕션 빌드로 Vue/CSS 구문과 에셋 번들을 확인한다.
- Chrome에서는 테스트 클래스로 top/bottom inset을 강제해 레이아웃을 빠르게 확인한다.
- 최종 승인은 실제 iPhone Safari와 홈 화면 PWA에서 로그인 키보드, 홈 헤더, 목록 스크롤, QR·카메라 버튼, 하단 메뉴를 확인한다.
